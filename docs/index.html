WHAT THIS PROVES

Not just configured — verified.

Every row below was built, then tested with real traffic, real logs, or a real deliberately-induced failure — not assumed to work because the config looked right.

RU 01

Segmentation

4 VLANs — Trusted, Guest, Servers, DMZ — each with explicit, logged firewall policy, not just implicit default-deny. Guest→Trusted isolation proven with real log evidence.

RU 02

Remote access

SSL-VPN on a non-default port, dynamic DNS via DuckDNS, tested end-to-end from real cellular data — including a 5-cause bug chain to get there.

RU 03

Site-to-site

A physically separate branch office, dynamically routed back to HQ over RIPv2, isolated from internal VLANs by policy, internet-only.

RU 04

Monitoring

Prometheus + Grafana, SNMP polling of every core device, live dashboards — with a documented, honestly-labeled limitation on containerized memory accounting.

RU 05

Automation

Bash + cron nightly diffing config backups on all three core devices, plus a config-drift isolation checker validated against a deliberately broken policy.

RU 06

Detection

A real reconnaissance simulation from the DMZ, confirmed blocked using a live FortiGate packet sniffer when standard log views came up empty.

FAULT LOG

A few incidents, in brief

The full record — every bug, every root cause — lives in TROUBLESHOOTING-LOG.md. Four representative ones below.

PART 11 · SSL-VPN

A cipher list that banned its own requirements

SSL-VPN failed with a generic "SSL exit error." show full-configuration revealed the firewall had banned SHA256/SHA384 while its own cipher suite required them — zero valid ciphers left.

Fix: selectively un-banned the two hashes actually needed, left SHA1 excluded.

PART 11 · Client-side

The firewall wasn't the problem — a VPN client was

Every server-side fix still failed. The dominant cause: Tailscale on the test phone, competing with FortiClient for the device's VPN routing.

Fix: disabled the competing client. Immediate, clean connection.

PART 15/16 · Automation

A drift-detection script that couldn't detect drift

The isolation-checker passed every test — until validated against a real, intentionally-disabled policy. It missed it. The field that mattered was written before the anchor point it searched from.

Fix: rewrote to parse whole policy blocks, re-tested against the same real fault, confirmed caught.

PART 17 · Detection

Silence in the logs isn't proof of nothing happening

A real port scan from DMZ into Trusted was blocked — but produced zero entries in Forward Traffic, Local Traffic, or Security Events.

Fix: diagnose sniffer packet on the FortiGate CLI proved packets arrived and were silently denied — a logging distinction the GUI never surfaces.
